# SQLWatcher Production Cleanup Report

Date: June 2026

This cleanup pass was based on the updated build audit and focuses on removing non-production artefacts, reducing UI invalidation load, and aligning deployment configuration with Fly.io compatibility.

## Removed from the production package

- Python bytecode caches: all `__pycache__/`, `*.pyc`, and `*.pyo` files.
- Dead service adapter: `backend/app/services/detection_engine.py`.
- Redundant dependency file: `backend/requirements-ml.txt`.
- Legacy SecureShop fallback bundle: `secureshop/frontend/static/`.
- Internal CSS audit artefact: `frontend/STYLE_CSS_AUDIT.md`.
- Unused frontend placeholder components: `frontend/src/pages/_shared/PageStub.tsx` and `PageStub.module.css`.
- External analysis report from repo root: `SQLWatcher_Production_Analysis.md`.
- Drift-prone manual schema dump: `database/schema.sql`.

## Moved

- `PRODUCTION_READINESS.md` → `docs/PRODUCTION_READINESS.md`.
- `PRODUCTION_AUDIT_REPORT.md` → `docs/PRODUCTION_AUDIT_REPORT.md`.

## Updated

- Added a root `.gitignore` with recursive Python cache, environment, Node build, local artefact, and legacy static exclusions.
- Strengthened all `.dockerignore` files to exclude caches, stale audit outputs, analysis reports, and legacy frontend fallback content.
- Rewrote `docs/architecture.md` to reflect the current production topology: Vercel frontends, Render APIs, Fly.io PostgreSQL proxy, and Neon databases.
- Rewrote `README.md` into a production-focused handoff README.
- Updated `README_LOCAL_ENV.md` to clarify that backend migrations are the SQLWatcher schema source of truth and `database/secureshop_schema.sql` is only for SecureShop target data.
- Scoped `new_alert` WebSocket invalidation in `Shell.tsx` to `alerts` and `stats` only. Heavier logs/timeline/performance refreshes are left to the rate-limited `sync_required` path.
- Updated `proxy/fly.toml` to use `1gb` shared CPU for Fly compatibility. `performance` CPU can require 2GB RAM depending on account/region.

## Validation

Python syntax compilation passed for:

- `backend/app`
- `proxy/sqlwatcher_pg_proxy.py`
- `secureshop/backend/app`

Generated bytecode was deleted after validation so the release archive remains clean.
